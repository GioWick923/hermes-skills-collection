# Plateau Strategies — 平台期破局指南

## 什么是平台期？

分数连续 N 轮（默认 2）不提升。表现为：
- Agent A 修复了扣分项，但 Agent B 给出相同或更低的分数
- 不同扣分项此消彼长（修了 A 又冒出 B）
- 分数在某个区间反复震荡

## 平台期的 5 种原因

### 原因 1：修复引入新问题
**症状：** 修了 scripts 的扣分，但 README 变脏了
**策略：** Agent A 的 prompt 加入："修改后检查 README 和 references 是否同步更新"

### 原因 2：评审标准不一致
**症状：** 同样的代码，不同轮次给不同分数
**策略：** Agent B 的 prompt 加入："参考上一轮评分，已修复的项必须加分，不得因新发现而扣回"

### 原因 3：扣分项超出能力范围
**症状：** 某个扣分项连续 3 轮没修好
**策略：** 标记为 "won't fix"，从目标分数中扣除，降低目标

### 原因 4：Agent A 没有真正理解扣分项
**症状：** Agent A 声称修了，但 Agent B 验证发现没变
**策略：** 在 feedback.md 中用更具体的指令：
```
❌ "references 内容太浅"
✅ "references/scoring-rubric.md 第 15-20 行只有概念描述，
    需要添加一个具体的评分示例，包含 3 个不同质量等级的打分过程"
```

### 原因 5：分数天花板
**症状：** 85-90 区间反复震荡
**策略：** 承认某些维度（如"迭代记录"需要真实 bug）在自动化场景下难以满分，
降低目标到当前最高分 + 2

## 平台期处理流程

```
检测到平台期
  │
  ▼
压缩旧 feedback（compress-feedback）
  │
  ▼
分析最近 2 轮的 stuck items
  │
  ├── 有明确 stuck item → 聚焦 top 3，忽略其他
  │
  ├── 扣分项此消彼长 → 检查评审一致性
  │
  └── 全部都 stuck → 降低目标或终止
  │
  ▼
更新 feedback.md（追加平台期分析）
  │
  ▼
继续下一轮（聚焦模式）
```

## 聚焦模式 Prompt

当进入平台期时，Agent A 的 prompt 改为：

```
你现在处于聚焦模式。分数已经连续 {N} 轮没有提升。

只修复以下问题，完全忽略其他扣分项：
{top_3_stuck_items}

如果某个问题你认为无法修复，请诚实说明原因，不要假装修了。

修改后，对比修复前后的代码差异，确认改动确实解决了问题。
```

## 终止条件

以下情况应终止循环并报告用户：

| 条件 | 处理 |
|------|------|
| 连续 3 轮分数完全相同 | 终止，报告 stuck items |
| 分数下降 2 轮 | 暂停，询问用户是否继续 |
| 已达 max_rounds | 终止，报告最终分数 |
| Agent A 明确表示某项无法修复 | 评估是否调整目标分数 |

## 向用户报告平台期

```
⚠️ 分数卡在 {score}/{target}，连续 {N} 轮未提升。

卡住的问题：
1. {item} — 已尝试 {approach}，未成功
2. {item} — 修复后引入新问题

建议：
A) 继续自动迭代（再跑 2 轮，聚焦 top 1 问题）
B) 手动介入（你来决定怎么改）
C) 降低目标到 {score + 2}
D) 终止，接受当前分数
```
